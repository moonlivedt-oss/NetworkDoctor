## Что это

Обычные «сетевые» утилиты либо показывают состояние, либо грубо сбрасывают весь стек.
**NetworkDoctor** — это фокусированный инструмент под один конкретный сценарий: когда после
прокси-клиентов (Happ, Nekoray, v2rayN, Clash…) и туннелей (WireGuard, sing-tun) интернет
ломается, а *почему* — непонятно.

Он сначала **разбирается**, что именно застряло (мёртвый прокси, kill-switch файрвола,
зависшие маршруты, заниженный MTU, подмена DNS/hosts), показывает это карточками — и только
потом чинит, начиная с самого безопасного шага и **останавливаясь, как только интернет вернулся**.

| | Ручной сброс (`netsh …`) | «Кнопка сброса сети» | NetworkDoctor |
|---|---|---|---|
| Понять *причину* | нет | нет | **да, карточки диагностики** |
| Начать с безопасного шага | вручную | нет (сразу всё) | **да, эскалация «Починить умно»** |
| Не трогать активный прокси зря | — | нет | **да, вывод срабатывает только если прокси реально включён** |
| Чистка остатков VPN (kill-switch/маршруты/MTU) | по одному | нет | **да, одной кнопкой + бэкап** |
| Бэкап перед сбросом | нет | нет | **да, файрвол/hosts/снимок сети в `logs/backups`** |
| Фоновый мониторинг + авто-починка | нет | нет | **да, с уведомлениями Windows** |
| Внешние зависимости | — | — | **одна (PyQt6)** |

## Зачем

При активном использовании прокси и туннелей в системе накапливается мусор:

- **застревает мёртвый прокси** — приложение прописало прокси в Windows, но при выходе не убрало
  → система ходит через несуществующий сервер → интернета нет;
- **застревает kill-switch файрвола** — VPN оставил блокирующее правило после падения → трафик
  заблокирован целиком;
- **зависают маршруты** мёртвых туннелей — трафик уходит через несуществующий шлюз;
- **занижается MTU** — часть сайтов «висит» или грузится наполовину;
- **ломается Winsock / TCP-стек** после множества подключений виртуальных адаптеров;
- **кешируется DNS** отключённых VPN-серверов; висят переменные `HTTP_PROXY` / `HTTPS_PROXY`.

## Возможности

**Главное:**

- **Автодиагностика при запуске** — окно открылось, состояние уже проверяется.
- **Сводный индикатор состояния** — крупная плашка вверху: «Интернет работает нормально» /
  «есть замечания» / «похоже, есть проблема» одним взглядом.
- **Починить умно** — одна кнопка: сама делает нужные шаги по порядку (сброс прокси + DNS →
  чистка зависших маршрутов и перезапуск службы DNS, если есть права админа → при необходимости
  обновление IP) и **останавливается, как только интернет вернулся**. Без перезагрузки, не
  завершает приложения.
- **Рекомендация после диагностики** — по результатам проверки приложение подсказывает **одно
  лучшее действие** и запускает его одной кнопкой (например, «Убрать остатки VPN» при найденном
  kill-switch или «Быстрая починка прокси» при застрявшем прокси).
- **Перезапуск с правами администратора** — если запущено без прав, кнопка вверху окна
  перезапускает через UAC (не нужно вручную искать `.bat`).
- **Авто-починка** — тумблер в шапке (работает вместе с мониторингом): если интернет пропал,
  сам запускает «Починить умно» и уведомляет о результате. Внимание: сбрасывает системный прокси,
  поэтому может отключить активный прокси-клиент — включай, если прокси не используешь.
- **Быстрая диагностика** — основные карточки показываются за пару секунд, а медленные проверки
  «остатков VPN» (файрвол/маршруты) догружаются в фоне. Системное состояние собирается одним
  запросом PowerShell вместо шести.
- **Фоновый мониторинг** — тумблер в шапке. Тихо следит за интернетом и присылает уведомление
  Windows при обрыве. Также отслеживает **выходной узел** (внешний IP + страну через Cloudflare
  trace) и предупреждает, когда выход прыгнул (напр. Япония→Германия). Проверка связи идёт лёгким
  HTTPS-запросом каждый интервал (по умолчанию 20 с, настраивается), а внешний IP/страна
  запрашиваются заметно реже — чтобы не дёргать внешний сервис круглосуточно.
- Мягкая тёмная/светлая тема, своя иконка, плавные анимации, спиннер при проверке.
- **Тихая авто-проверка обновлений** при запуске (раз в сутки, сообщает только если версия
  доступна) — включается в настройках.
- **Горячие клавиши**: `F5` — проверить сеть, `Ctrl+R` — починить умно, `Ctrl+U` — обновления,
  `F1` — о программе. Приложение запоминает размер и положение окна между запусками.

## Диагностика

Показывает, ничего не меняя:

- системный прокси Windows (WinINET) — как для текущего пользователя (HKCU), так и уровня всей
  машины (HKLM: групповая политика или стороннее ПО);
- WinHTTP-прокси;
- переменные окружения прокси (пустые игнорируются);
- виртуальные адаптеры VPN/туннелей и их статус;
- **умная проверка связи**: отдельно «сырой» TCP и HTTPS через системные настройки. Вывод
  «застрял прокси» срабатывает только если прокси реально включён — чтобы активный туннель не
  выглядел как поломка;
- **остатки VPN**: блок-правила брандмауэра (kill-switch), зависшие маршруты от мёртвых
  туннелей, нестандартные записи в файле hosts (безвредные dev-записи вроде Docker не считаются
  проблемой) и заниженный MTU адаптера.

## Починка

Каждое действие — с подтверждением и понятным описанием того, что произойдёт.

- **Быстрая починка прокси** — сброс WinINET + WinHTTP + переменных окружения + отключение
  авто-определения прокси (WPAD/PAC) + очистка DNS. Безопасно, без перезагрузки. После —
  авто-перепроверка.
- **Обновить IP** — `ipconfig /release` + `/renew`.
- **Убрать остатки VPN** — сброс брандмауэра к умолчаниям (снимает застрявший kill-switch),
  удаление зависших маршрутов, возврат MTU к 1500, очистка ARP-кеша, чистка подозрительных
  записей hosts и перезапуск службы DNS. Без перезагрузки, требует админа. Лечит «после VPN
  интернет заблокирован целиком» и «часть сайтов висит». Перед сбросом правила брандмауэра и
  hosts сохраняются в `logs/backups` (откат брандмауэра: `netsh advfirewall import`).
- **Глубокий сброс сети** — `netsh winsock reset` + `netsh int ip reset`. Требует прав
  администратора и **перезагрузки**. Перед сбросом создаётся точка восстановления системы (если
  «Восстановление системы» включено) и снимок сетевых настроек (`ipconfig /all`, маршруты,
  правила файрвола) в `logs/backups`.

| Инструмент | Что делает | Права |
|---|---|---|
| **Зависшие прокси-процессы** | процессы на прокси-портах (1080, 10808, 2080…) или с именами прокси-клиентов (sing-box, xray, nekoray…), с кнопкой «Завершить» | — |
| **Перезапустить адаптер** | отключить/включить сетевой адаптер без перезагрузки | админ |
| **Переключить DNS** | 1.1.1.1 (Cloudflare) / 8.8.8.8 (Google) или авто (DHCP) | админ |

| **Переключить IPv6** | вкл/выкл IPv6 на активном адаптере — частый виновник глюков после VPN | админ |
| **Текущий DNS / утечка** | какие DNS реально используются на адаптерах + подсказка об утечке | — |
| **Активные соединения** | внешние TCP-соединения с именем процесса — куда подключён ПК | — |
| **Детали адаптера** | IP, шлюз, DNS, MAC, скорость линка, режим DHCP | — |
| **Пинг хоста** | задержка и потери до любого IP/домена (хост по умолчанию — из настроек) | — |
| **Подобрать MTU** | DF-пингом находит оптимальный MTU и предлагает установить его | админ (установка) |
| **Тест DNS-серверов** | замеряет задержку публичных резолверов (Cloudflare, Google, Quad9, OpenDNS, Яндекс) сырым UDP-запросом и подсказывает самый быстрый | — |

**Логи и история** (в шапке журнала внизу окна):

- **Логи** — всё, что делает утилита, и любые ошибки пишутся в `logs/netdoctor.log`
  (ротация 5×1 МБ). Необработанные падения тоже попадают в файл.
- **История состояний** — снимки диагностики, выполненные починки и события монитора (когда
  пропадал интернет, когда менялся выходной узел) построчно в `logs/network_state.jsonl`.
- **Копировать / Отчёт** — отчёт (диагностика + журнал, с версией и сведениями о системе) в буфер
  обмена или в текстовый файл. Работает офлайн — можно выгрузить, даже когда интернета нет. В окнах
  соединений, деталей адаптера и DNS есть свои кнопки «Копировать».
- **Откат файрвола** — восстановить правила брандмауэра из ранее сохранённого бэкапа `.wfw`
  (откат сброса, сделанного в «Убрать остатки VPN»).
- **О программе** — версия, права администратора, ссылка на репозиторий, путь к папке логов.
- **Папка логов** — открыть папку `logs` в проводнике.

**Автозапуск и трей:**

- **Автозапуск** — запускать вместе с Windows свёрнутым в трей (через `HKCU\…\Run`, без прав
  админа), чтобы мониторинг был всегда наготове.
- **Сворачивание в трей** — при включённом мониторинге закрытие окна прячет программу в трей
  (мониторинг продолжает работать). Полностью закрыть — правый клик по значку → «Выход».

## Запуск

Требуется Windows и Python 3.10+ с установленным PyQt6.

```bash
pip install -r requirements.txt
```

- **`Запуск.bat`** — обычный запуск. Диагностика и быстрая починка прокси работают.
- **`Запуск (админ).bat`** — с правами администратора (запросит UAC). Нужен для «глубокого сброса
  сети» и чистки остатков VPN.

Оба `.bat` запускают `run.pyw` (launcher пакета). Можно и напрямую:

```bash
python -m netdoctor      # из корня проекта
pythonw run.pyw          # без окна консоли
```

Либо установить пакет целиком (появится команда `networkdoctor`):

```bash
pip install .
```

## Как пользоваться

1. Запусти — окно **само проверит сеть** и покажет сводную плашку состояния вверху.
2. Если есть проблема — жми **«Починить умно»**: утилита пройдёт безопасные шаги по порядку и
   остановится, как только связь вернётся.
3. Не помогло — точечные кнопки: **«Убрать остатки VPN»** (kill-switch/маршруты/MTU),
   **«Зависшие прокси-процессы»**, **«Перезапустить адаптер»**, в крайнем случае **«Глубокий
   сброс сети»** (нужна перезагрузка).
4. Хочешь, чтобы следило само — включи **«Мониторинг»** (и, при желании, **«Авто-починку»**);
   окно можно закрыть — оно свернётся в трей.

> Внимание: если ты **сейчас пользуешься** прокси-клиентом через системный прокси, «Быстрая починка»
> и «Починить умно» его отключат (они сбрасывают системный прокси). Это ожидаемо — включай их,
> когда прокси уже не нужен, или используй точечные инструменты.

## Настройки и обновления

- **Настройки** — тёмная/светлая тема и акцентный цвет (применяются на лету, без перезапуска),
  хост по умолчанию для «Пинг хоста», период проверки фонового мониторинга и тумблер тихой
  авто-проверки обновлений. Хранятся в `logs/config.json`. Состояние авто-починки, размер/позиция
  окна тоже запоминаются между запусками.
- **Обновления** — проверка новой версии на GitHub (вручную кнопкой или тихо при запуске раз в
  сутки). Репозиторий задаётся **без правки кода** — ключ `"github_repo"` (в формате
  `"владелец/название"`) в `logs/config.json`; как запасной вариант можно вписать его в
  `netdoctor/updates.py` → `GITHUB_REPO`.

## Структура проекта

Приложение — пакет `netdoctor/`. Модули верхнего уровня — инфраструктура и точка входа,
сетевая логика вынесена в подпакет `net/`, представление (Qt) — в `ui/`:

| модуль | за что отвечает |
|--------|-----------------|
| `core.py` | права админа, запуск команд (абс. пути к System32), `ps_quote`, константы |
| `logs.py` | файловые логи, история состояний (JSONL), текстовые отчёты |
| `settings.py` | пользовательские настройки (`config.json`) с типизацией значений |
| `updates.py` | проверка новой версии на GitHub |
| `autostart.py` | автозапуск с Windows (в т.ч. для `.exe`-сборки) |
| `workers.py` | фоновые потоки (QThread): диагностика, починка, монитор |
| `app.py` | главное окно и `main()` |
| `net/tools.py` | процессы, адаптеры, DNS, внешний IP, скорость, соединения, MTU |
| `net/diagnostics.py` | проверки сети (прокси, адаптеры, связь, остатки VPN) |
| `net/fixes.py` | починка (прокси, DNS, IP, Winsock/TCP, файрвол, маршруты, MTU) + бэкапы |
| `net/hosts.py` | путь, разбор и оценка подозрительности записей файла hosts |
| `ui/theme.py` | тёмная/светлая палитры, стили Qt, иконка, спиннер |
| `ui/dialogs.py` | диалоговые окна |


## Сборка в .exe

Чтобы запускать без установленного Python:

```bash
pip install -r requirements.txt pyinstaller
```

Затем запусти **`Собрать exe.bat`** (или вручную
`pyinstaller --onefile --noconsole --name NetworkDoctor run.pyw`). Готовый файл появится в
`dist\NetworkDoctor.exe`. Автозапуск умеет ссылаться на собранный `.exe` (а не на python-скрипт),
если включён из `.exe`-сборки.

## Безопасность

Утилита выполняет системные команды и правит реестр — поэтому сделана консервативно:

- **Нет `shell=True`** — команды запускаются списком аргументов (`subprocess.run(args, …)`),
  без разбора строки оболочкой; окно консоли подавляется (`CREATE_NO_WINDOW`).
- **Защита от инъекций** — пользовательский ввод (хост для пинга) проходит через `valid_host`
  (строгий регэксп: только буквы/цифры/`.`/`-`/`:`, длина ≤ 253), а имена адаптеров и другие
  значения, подставляемые в PowerShell, экранируются через `ps_quote` (`'` → `''`).
- **Проверка внешних входных данных** — репозиторий обновлений из `config.json` валидируется по
  формату `владелец/название` (чтобы подменённый конфиг не увёл запрос на чужой адрес), а ответы
  из сети читаются с лимитом размера (обновления, внешний IP, замер скорости) — защита от
  «бесконечного» тела ответа.
- **Бэкапы перед разрушительными действиями** — правила брандмауэра (`netsh advfirewall export`),
  файл hosts и снимок сетевых настроек сохраняются в `logs/backups` до сброса; перед глубоким
  сбросом создаётся точка восстановления системы.
- **Аккуратная чистка hosts** — удаляются **только** подозрительные записи (реальные домены,
  уведённые на loopback/0.0.0.0); комментарии и dev-записи (Docker и т.п.) сохраняются.
- **Запуск утилит по абсолютному пути** — системные команды (`netsh`, `powershell`, `ping`…)
  вызываются из `%SystemRoot%\System32`, а не по «голому» имени, чтобы исключить подмену
  исполняемого файла из текущей папки (binary planting) — особенно важно при запуске с правами
  администратора.
- **Устойчивость к битому конфигу** — значения из `config.json` приводятся к ожидаемому типу при
  загрузке; повреждённый или подменённый файл не уронит программу и не подсунет неожиданный тип.
- **Понятные подтверждения** — каждое изменяющее действие показывает, что именно произойдёт, и
  требует явного согласия; для операций, которым нужен админ, есть отдельная проверка прав.

> Примечание о приватности: отчёт и история содержат ваш **внешний IP** и конфигурацию сети
> (адаптеры, DNS, маршруты) — они нужны для разбора проблемы, но просмотрите отчёт перед
> отправкой в чат/тикет.
